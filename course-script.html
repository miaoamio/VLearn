开场

0:00 - 5:00 | 5 分钟
OPENING 翻车故事 + 引入概念 5 min
小绿 大家好！在正式开始之前，我先讲一个我自己的惨痛经历。上周五下午，我跟 agent 一起改一个页面，改了大概两个小时，越改越好看。然后——断网了。
小绿 我重新打开的时候发现……agent 把我之前那版好的代码全覆盖了。两个小时，白干。我当时的表情大概是这样的：🙂（微笑面具下的崩溃）
小红 哈哈哈我知道那种感觉！就像你在 Figma 里做了一个超好的方案，结果发现没保存直接关了页面。
小绿 对！但 Figma 至少还有版本历史。代码呢？如果你没做任何准备，那就真的没了。所以今天我们要学的这个东西——Git——本质上就是一个自动存档系统。
小绿 想想你打游戏，每过一关是不是要存个档？写代码也一样。每做完一步，存个档。翻车了？读档！就这么简单。
小红 那我们今天怎么练？不会真的要在终端里敲命令吧？
小绿 当然不会！我们有一个可视化沙盒——你可以理解为一个"做三明治"的小游戏。左边是你的三明治工作台，你可以加层、删层、换食材；右边是一个树状图，展示你的存档记录。所有概念我们都用做三明治来理解。
  • 打开沙盒工具页面，确认大家都能看到左侧三明治编辑区 + 右侧 Git 树图
  • 简单演示：点一下"加一层牛肉"，看看左侧三明治变化
开场的核心目标是让学员产生共鸣（"我也遇到过这种事！"），同时把 Git 的心智模型简化为"存档/读档"。不要在这里展开任何技术细节。

幕一：独自开发

5:00 - 25:00 | 20 分钟
ROUND 0 建仓库 init / 远端仓库 3 min | 5:00-8:00
小绿 好，假设我现在要开一个新项目。跟 agent 说"帮我做一个咖啡店官网"，agent 噼里啪啦给我写了一堆代码。但这时候——这些代码没有存档系统！就像你开了一家店但没有账本，赚了多少亏了多少全靠记忆。
小红 所以第一步是什么？先装一个存档系统？
小绿 对！在 Git 里这叫 init——初始化。你跟 agent 说"帮我初始化一个 Git 仓库"，它就在你的项目里装好了存档系统。从这一刻起，你就可以开始存档了。
小绿 但是！现在这个存档只在你自己电脑上。如果你想备份到云端，或者以后让小红也能参与——你需要在网上建一个"远端仓库"。你可以让 agent 帮你在 GitHub 上建一个。
小红 GitHub 是什么？
小绿 你可以理解为"代码界的百度网盘"——一个放代码的云端。你的存档放一份在本地，再推一份到云端。电脑炸了也不怕，云端有备份。以后队友想参与，从云端把项目拉下来就行。
小红 那我要是加入一个已有的项目呢？比如你已经做好了，我后面才加入。
小绿 那你就 clone——把云端的项目完整复制到你本地。就像你入职新公司第一天，从公司网盘把整个项目文件夹下载到自己电脑。这个我们等下到幕二再演示。
  • 在沙盒中展示初始状态（空白/只有初始节点）
  • 解释："init 之后就有了这个树图的起点"
  • 简要提及 GitHub，不展开操作（学员不需要现在建）
  • 用三明治比喻：init = 你决定开一家三明治店，并且买了一个记账本
这个环节不用学员动手操作，纯讲解 + 演示。目标是让学员理解"仓库"的概念：本地仓库 = 你的记账本，远端仓库 = 云端备份。实际操作中，agent 会帮你搞定 init 和创建远端仓库。
ROUND 1 存档 commit 5 min | 8:00-13:00
小绿 好，现在我来做个三明治。先加一层牛肉……嗯不错，再把原来的芝士换成生菜，健康一点。
小绿 （对着观众）好了做完了！现在大家注意看，我不存档，直接关掉页面——
小绿 （重新打开）诶？我的牛肉呢？我的生菜呢？全没了！回到了最初的样子。完蛋。
小红 哈哈哈你这不就是写了半天代码没 save 的感觉吗？
小绿 对！所以关键来了——做完一步之后，你要点"存档"，Git 里叫 commit。存档的时候要写一句话说明你干了什么。比如我这次写："加了牛肉层，把芝士换成生菜"。
小绿 （操作演示）看，右边的树图上多了一个节点！这就是我的第一个存档点。以后不管发生什么事，我都能回到这个点。
小红 就像游戏里的快速存档？
小绿 完全正确！而且你可以存无数个档。每做完一步就存一个。这样就算 agent 后面把你的东西搞乱了，你随时能回来。
  • 在沙盒中：添加"牛肉"层，将"芝士"替换为"生菜"
  • 不存档 → 刷新页面 → 展示数据丢失
  • 重新操作一遍 → 点击"存档 (commit)" → 输入描述信息
  • 指着右侧树图，解释"这个圆点就是你的存档"
  • 在沙盒里随意编辑三明治（至少改 2 个地方）
  • 点击"存档"，写一句话描述你做了什么
  • 确认右侧树图出现新节点
ROUND 2 读档 reset 5 min | 10:00-15:00
小绿 好，我继续改三明治。我觉得……加个榴莲？再加个巧克力酱？哦对了把面包换成年糕！创意爆棚！
小红 （皱眉）你这做的是三明治还是暗黑料理……
小绿 emmm 好像确实有点过了。我想回到刚才那版——就是有牛肉和生菜的那个正常版本。怎么办？
小红 读档啊！你刚才存了不是吗？
小绿 对！在 Git 里这叫 reset——时光倒流。我点一下之前那个存档节点……（操作）看！榴莲没了，巧克力没了，年糕也没了。回到了正常的牛肉生菜三明治。
小绿 这就是为什么要频繁存档的原因——你存的档越多，能回退的选择就越多。就跟游戏一样，如果你只在第一关存了档，打到第十关翻车了，你只能回第一关从头来。
小红 血泪教训。所以做 vibe coding 的时候，你跟 agent 说"帮我存个档"就行了？
小绿 没错！你甚至可以跟 agent 说"每做完一个功能就自动帮我 commit 一次"。
  • 继续编辑三明治：加一些"奇怪的层"（榴莲、巧克力等）
  • 先存一个"暗黑料理版"的档（让学员看到树图上有两个节点）
  • 点击之前的存档节点 → 执行 reset
  • 展示三明治恢复到之前的状态
  • 在之前的三明治上乱改一通（尽情发挥）
  • 存个档（记录"暗黑版"）
  • 然后 reset 回到上一个正常版本
  • 确认三明治恢复了
ROUND 3 开分支 branch 5 min | 15:00-20:00
小绿 现在我有个新需求——我想同时试两个方向：一个是"日式风味"三明治（三文鱼 + 海苔），另一个是"美式风味"（培根 + 芝士 + BBQ 酱）。
小红 那你先做完一个再做另一个呗？
小绿 但我不想丢掉任何一个方向的进度啊。而且做设计的时候你是不是也经常开好几个方案同时探索？Figma 里你会开多个 Frame 对吧？
小红 对对对，方案 A、方案 B、方案 C。
小绿 Git 里也有这个功能，叫 branch——分支。你从当前这个点"岔"出一条新路。在新路上随便折腾，原来那条路完全不受影响。
小绿 （操作）我现在开一条分支叫"日式风味"……看右边的树图，是不是分叉了？在这条线上我加三文鱼、加海苔。原来的主线上还是牛肉生菜，纹丝不动。
小红 哦就像平行宇宙！这边的我在吃三文鱼，那边的我在吃牛肉，互不打扰。
小绿 完美的比喻！而且你可以随时切换过去看另一条线的样子。想想 vibe coding 的场景：你让 agent 帮你试一个大改动，但你不确定行不行——那就开个分支让它去试，试坏了也不影响你原来能跑的版本。
  • 从当前节点创建新分支"日式风味"
  • 在新分支上编辑：添加三文鱼层、海苔层
  • 存档
  • 切回主线 → 展示三明治没变
  • 指着右侧树图解释"分叉"的含义
  • 从当前主线开一条新分支，随便取个名字
  • 在新分支上改三明治（至少改 2 处）
  • 存档
  • 切回主线，确认三明治没变
ROUND 4 合并 merge 5 min | 20:00-25:00
小绿 好消息！我试了一圈发现日式风味那个三文鱼层特别好吃。我想把它搬回主线里来。
小红 就像你做了三个设计方案，最后跟客户说"方案 B 的那个配色不错，我拿过来用到方案 A 里"？
小绿 一模一样！Git 里这个操作叫 merge——合并。把另一条分支上的好东西搬回主线。
小绿 （操作）我切到主线，然后告诉 Git："把日式风味合过来"……看！三文鱼出现在主线的三明治里了。右边的树图上，两条线汇合了。
小红 这也太方便了吧。但如果主线上这个位置已经有东西了呢？
小绿 好问题！如果主线在这段时间没动过，Git 会直接"快进"把改动搬过来——这叫 fast-forward，像排队时前面的人走了你直接往前挪。但如果主线也改了，Git 就要做一次"真正的合并"，像把两份菜单的优点整合到一起。
小绿 大多数时候 Git 能自动搞定。但如果两边改了同一个位置——那就冲突了。这个我们等会在幕二详细讲。
  • 切到主线（main）
  • 执行 merge：合并"日式风味"分支
  • 展示合并结果（三文鱼出现在主线三明治中）
  • 展示 fast-forward 的树图效果
  • （可选）演示主线有改动时的合并效果
  • 切到主线
  • 将你之前的实验分支合并回主线
  • 确认主线三明治拿到了分支上的改动
  • 观察右侧树图的汇合效果

幕二：GitHub 真实协作实操

25:00 - 55:00 | 30 分钟
切换环节提示：从这里开始，离开沙盒模拟器，进入真实 GitHub 仓库。讲师提前建好了一个协作仓库，学员现场被邀请为 collaborator，在 TraeWork 里跟 agent 对话完成所有操作。
ROUND 5 加入项目：clone + 环境搭建 5 min | 25:00-30:00
小绿 好！概念建立完了，现在来真的。我已经建好了一个 GitHub 仓库，等下会把邀请链接发到群里——大家点接受，就正式成为这个项目的协作者了。
小红 相当于入职第一天对吧？先领工位、再下载公司项目。
小绿 对！在 TraeWork 里，你只需要跟 agent 说一句话："帮我 clone 这个仓库 [粘贴仓库地址]"。agent 会自动帮你下载整个项目到本地。
小绿 clone 完了大家看一下——是不是跟刚才沙盒里一样？有一个初始版本，有一条 main 分支。刚才在沙盒里看到的那棵树，现在是真的了。
小红 （带着大家确认）大家都 clone 成功了吗？能看到项目文件了吧？
  • 接受 GitHub 邀请（群里发链接）
  • 在 TraeWork 里跟 agent 说"帮我 clone [仓库地址]"
  • 确认项目文件已下载
ROUND 6 独立开发：branch + commit + push + MR 10 min | 30:00-40:00
小绿 好，现在每个人都要做一件事：给这个项目加点自己的东西。但！还记得我们刚才说的吗？不要直接改 main。
小红 在营业中的店里装修会吓跑客人！
小绿 所以第一步：跟 agent 说"帮我开一个新分支，叫 feature/我的名字"。比如 feature/xiaoming。这样你的改动就在旁边的一条线上，不影响 main。
小绿 然后——随便改点什么。改个标题、加一段文字、换个颜色——你说了算，agent 帮你写。
小红 改完了记得说什么？
小绿 "帮我存个档，备注'加了 xxx'"！然后"帮我 push 到远端"。这样你的改动就上传到 GitHub 了。
小绿 最后一步——去 GitHub 上提一个 MR。你可以跟 agent 说"帮我创建一个 Pull Request，合并到 main"。这样队友就能看到你改了什么。
小红 我先来演示一遍！（实操演示完整流程）
  • 跟 agent 说"帮我开一个分支叫 feature/你的名字"
  • 让 agent 帮你做一处修改（自由发挥）
  • "帮我存个档，备注'改了 xxx'"
  • "帮我 push 到远端"
  • "帮我创建一个 Pull Request 合并到 main"
这是学员第一次真实操作 Git 全流程。节奏要慢，每一步等大家都完成再进入下一步。讲师可以投屏 GitHub 页面，让大家看到 PR 被创建的样子。
ROUND 7 Code Review + 合并 5 min | 40:00-45:00
小绿 好，现在我打开 GitHub 看看——哇！你们提了一堆 PR 上来！（投屏展示 PR 列表）
小红 我来当主厨！让我看看你们的三明治——啊不是，你们的代码。
小绿 大家看这个界面——左边绿色的是新增的内容，红色的是删掉的。这就是 diff，跟我们沙盒里的三明治 diff 一模一样。
小红 （Review 某个 PR）嗯，这个同学加了一段很好看的样式——我 approve 了！点"Merge"——合进 main 了！
小绿 看到了吗？从分支到 MR 到 Review 到合并——这就是一个完整的协作闭环。每一步都有记录，谁改了什么一目了然。
  • 投屏 GitHub PR 页面，现场 Review 2-3 个学员的 PR
  • 展示 diff 视图，跟沙盒里的三明治 diff 做类比
  • 现场合并 1-2 个 PR 让大家看到效果
ROUND 8 冲突实战：真实 conflict 7 min | 45:00-52:00
小绿 刚才大家改的是不同的文件，所以合并顺利。但现在——我要故意制造一次冲突！
小红 来了来了，翻车现场！
小绿 我现在让两个同学改同一个文件的同一行——比如首页的标题。张三把标题改成"早安咖啡"，李四把标题改成"午后拿铁"。两个人都 push 了自己的分支，都提了 MR。
小绿 我先合了张三的——没问题。现在合李四的——
小红 （看屏幕）啊！GitHub 说"有冲突，不能自动合并"！
小绿 跟沙盒里一模一样！因为两个人改了同一个位置——标题这一行。Git 不知道该用"早安咖啡"还是"午后拿铁"。
小绿 解决方法？跟 agent 说"帮我解决冲突，用我的版本"或者"把两个都保留"。agent 会帮你处理那些奇怪的冲突标记。
小红 所以冲突不可怕——跟沙盒里练的一样，就是 Git 在问你"留哪个"。现实中你让 agent 帮你解决就行。
  • 观看讲师演示真实冲突
  • 有余力的同学：两两配对，故意改同一行，触发冲突，用 agent 解决
  • 跟 agent 说"帮我 pull 最新的 main，如果有冲突就用我的版本"
如果时间紧张，这一轮可以只做讲师演示，不让每个学员都触发冲突。重点是让学员"见过"冲突长什么样，知道不可怕。
ROUND 9 .gitignore + 分支保护 + 小流量 3 min | 52:00-55:00
小绿 快问快答收尾！三个小知识点。第一：有些文件不该被 Git 管——密码文件、临时文件、本地配置。怎么办？
小红 告诉 Git "别管这些"？
小绿 对！有个文件叫 .gitignore，里面列的东西 Git 会假装看不见。跟 agent 说"帮我把 .env 加到 gitignore"就行了。
小绿 第二：分支保护——在 GitHub 设置里可以锁住 main 分支，强制所有人必须走 MR 才能合并。这样就不会有人手滑直接 push 到线上了。
小绿 第三：小流量/灰度——你做好了新功能，不一定要直接全量上线。可以先让一小部分用户试试。跟 agent 说"帮我加个 feature flag"，它就知道怎么做。
小红 三明治新方案先在一个窗口卖卖看！
小绿 完美比喻！这三个不用现在记住操作，只要知道"有这个东西"，以后遇到了你知道可以问 agent。
  • 展示 GitHub 仓库设置里的 Branch protection rules 界面
  • 展示 .gitignore 文件内容（可以在仓库里打开给大家看）
  • 这一轮纯讲解，不需要学员操作

收尾

55:00 - 60:00 | 5 分钟
ENDING 回顾 + 金句 + 彩蛋 5 min
小绿 好！一个小时过去了，快速回顾。跟 agent 做 vibe coding，Git 方面你只需要会说这几句话：
小红 来，我来数——
"帮我存个档" → commit
"帮我回到上一版" → reset
"帮我开个新分支试试" → branch
"帮我合回主线" → merge
"帮我推到远端" → push
"帮我同步最新版本" → pull
"帮我提个 MR" → Pull Request
小绿 七句话，覆盖 90% 的日常场景。不用记命令，agent 全帮你搞定。但你得知道什么时候该说哪句话——这就是今天建立的"心智模型"。
小红 最后一个彩蛋——今天的三明治沙盒模拟器，大家回去可以继续玩！链接会发到群里。
小绿 如果你今天只记住一句话——那就是："每做完一步，跟 agent 说'帮我存个档'。" 这一句话，能救你无数次。
小红 今天的课就到这里！大家去做三明治吧！——啊不是，去做 vibe coding 吧！
  • 投屏展示"七句话"清单
  • 分享三明治沙盒链接
  • 如有时间：现场 Q&A 5 分钟
